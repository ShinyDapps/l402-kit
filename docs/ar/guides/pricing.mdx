## جدول مرجعي للـ Satoshi

1 sat = 1/100,000,000 من Bitcoin. عند نقاط السعر الشائعة:

| سعر BTC | 1 sat | 10 sats | 100 sats | 1,000 sats |
|---|---|---|---|---|
| $50,000 | $0.0005 | $0.005 | $0.05 | $0.50 |
| $80,000 | $0.0008 | $0.008 | $0.08 | $0.80 |
| $100,000 | $0.001 | $0.01 | $0.10 | $1.00 |

مدفوعات Lightning Network لا تمتلك حداً أدنى للرسوم. دفعة بمقدار 1 sat تكلّف المُرسِل ~$0.0005 — وهو أمر مستحيل مع Stripe (الحد الأدنى $0.30).

## التسعير حسب حالة الاستخدام

| حالة الاستخدام | السعر المقترح | المنطق |
|---|---|---|
| استعلام بيانات بسيط (الطقس، سعر الصرف) | 1–10 sats | رخيص بما يكفي ليكون غير محسوس، ولكنه لا يزال ذا معنى |
| استدعاء API متميز (استنتاج LLM، البحث) | 10–100 sats | يغطي تكلفة الحوسبة، ويُرشّح إساءة الاستخدام |
| وصول لكل مستند / ملف | 50–500 sats | يعكس قيمة المحتوى |
| تقرير أو مجموعة بيانات عالية القيمة | 500–5,000 sats | يتنافس مع المعاملات الصغيرة بقيمة $0.50–$5 |
| البث الفوري (لكل جزء) | 1–5 sats | يتراكم بشكل طبيعي عبر البث |

هذه نقاط بداية. السعر الصحيح هو ما سيدفعه المستخدمون دون أي احتكاك.

## ابدأ بأسعار منخفضة، ثم ارفعها

نظراً لأن تغيير الأسعار يتطلب سطراً واحداً من الكود، فضّل الأسعار المنخفضة عند الإطلاق:

```typescript
l402({ priceSats: 10, lightning }) // ابدأ من هنا
l402({ priceSats: 100, lightning }) // ارفع السعر إذا استمر الطلب
```

بيانات الدفع في لوحة تحكم VS Code تُظهر لك حجم الاستدعاءات والإيرادات — استخدمها للمعايرة.

## المُدار مقابل Soberano على نطاق واسع

رسوم المُدار البالغة 0.3% تهم فقط عند الحجم الكبير:

| الحجم الشهري | رسوم المُدار | توفير Soberano |
|---|---|---|
| 1,000 sats | 3 sats | ضئيل جداً |
| 100,000 sats | 300 sats (~$0.24) | صغير |
| 10,000,000 sats | 30,000 sats (~$24) | يستحق التحويل |

**قاعدة عامة:** إذا كنت تعالج أقل من 1M sats/شهرياً (~$800 بسعر $80k/BTC)، فإن رسوم 0.3% تعدّ ضئيلة. استمر في استخدام Managed وركّز على البناء. انتقل إلى Soberano عندما يجعل الحجم ذلك مجدياً — فهو سطر واحد من الكود.

## التسعير لوكلاء الذكاء الاصطناعي

الوكلاء غير حساسين للسعر بطريقة مختلفة عن البشر — فهم لا يشعرون بوطأة الدفع، لكنهم يمتلكون حدوداً للميزانية تضعها جهات التشغيل.

**إرشادات عملية:**
- احتفظ بالأسعار دون 100 sats لكل استدعاء للاستخدام العام للوكلاء — فهذا يتناسب مع ميزانيات الجلسة النموذجية
- بالنسبة لأدوات الوكلاء عالية القيمة (تنفيذ الكود، تحليل المستندات)، فإن 100–1,000 sats مقبول
- استخدم `priceSats` بشكل ديناميكي إذا كانت تكلفتك تتفاوت حسب حجم المدخلات:

```typescript
app.post("/analyze", (req, res, next) => {
  const sats = Math.ceil(req.body.text.length / 100); // 1 sat per 100 chars
  l402({ priceSats: sats, lightning })(req, res, next);
}, handler);
```

## الوصول المتدرج مع نقاط نهاية متعددة

سعّر الطبقات المختلفة عن طريق التوجيه إلى نقاط نهاية مختلفة:

```typescript
// الطبقة المجانية — بيانات أساسية
app.get("/data/basic", handler);

// الطبقة المدفوعة — مجموعة بيانات كاملة، 10 sats
app.get("/data/premium", l402({ priceSats: 10, lightning }), handler);

// الطبقة عالية القيمة — بث فوري، 100 sats
app.get("/data/realtime", l402({ priceSats: 100, lightning }), handler);
```

كل نقطة نهاية تولّد فاتورتها الخاصة. يدفع المستخدمون لكل استدعاء — لا إدارة اشتراكات.

## اختبار التسعير الخاص بك

قبل الإطلاق، اختبر تدفق الدفع الكامل بمحفظة حقيقية:

1. اضبط `priceSats: 1` (1 sat ≈ $0.0008 — رخيص بما يكفي للاختبار بحرية)
2. استخدم [Wallet of Satoshi](https://walletofsatoshi.com) أو [Blink](https://dashboard.blink.sv) على هاتفك
3. استدعِ نقطة النهاية الخاصة بك، وامسح رمز QR للفاتورة، وتحقق من 200 OK
4. تحقق من [لوحة تحكم VS Code](https://marketplace.visualstudio.com/items?itemName=ShinyDapps.shinydapps-l402) أو محفظة Lightning الخاصة بك لتأكيد الاستلام

بعد التأكيد، اضبط سعرك الحقيقي وانشر.
