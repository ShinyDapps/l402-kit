## مقارنة مع Stripe

**تتفوق Stripe في**: التحقق من الهوية (KYC)، الفوترة المتكررة، تجربة بطاقات الائتمان، كشف الاحتيال، عقود المؤسسات.

**يتفوق l402-kit في**: المدفوعات الصغيرة (أقل من $0.01)، وكلاء الذكاء الاصطناعي، الوصول العالمي، انعدام استردادات المدفوعات، انعدام متطلبات الإعداد، التسوية الفورية.

الحد الأدنى لرسوم Stripe هو $0.30 + 2.9%. دفع مقداره 1 satoshi ($0.0006) عبر Stripe سيكلّف 50,000% كرسوم. يفرض l402-kit 0.3% فقط — لا شيء غير ذلك.

**الحكم**: ليسا منافسَين. Stripe مخصصة للاشتراكات. l402-kit مخصص للمدفوعات الصغيرة بنظام الدفع مقابل كل طلب. كثير من المشاريع ستستخدم كليهما.

## مقارنة مع MPP (Stripe + Tempo) — جديد، مارس 2026

المدفوعات متعددة الأطراف (MPP) هو بروتوكول جديد أعلنت عنه Stripe وTempo في مارس 2026. يتيح لطرفين تقسيم دفعة Stripe عند الدفع — على سبيل المثال، تأخذ منصة السوق 10% ويأخذ البائع 90%، وتتم التسوية في معاملة واحدة.

**نقاط قوة MPP**:
- دعم مؤسسي (شبكة تجار Stripe بالكامل)
- تجربة بطاقات ائتمان مألوفة
- التحقق من الهوية والامتثال مدمجَان
- تقسيم الإيرادات تلقائي

**أوجه قصور MPP في تحقيق الدخل من الواجهات البرمجية**:
- **الحد الأدنى للرسوم لا يزال $0.30** — لا يغيّر MPP اقتصاديات Stripe لكل معاملة. المدفوعات الصغيرة بمقدار 1 satoshi لا تزال مستحيلة اقتصادياً.
- **لا دعم لوكلاء الذكاء الاصطناعي** — يتطلب وجود إنسان يحمل بطاقة ائتمان ومتصفحاً. لا يمكن لوكيل مستقل إجراء دفعة MPP.
- **يشترط أن يكون كلا الطرفين عميلَين لدى Stripe** — لا وصول بدون إذن.
- **التسوية لا تزال تستغرق 2–7 أيام** — لا تسوية فورية.
- **لا إثبات تشفيري** — لا يزال بإمكان الدافع الاعتراض أو طلب استرداد المبلغ.

يحل MPP مشكلة **تقسيم الإيرادات** في مدفوعات منصات السوق. أما L402 فيحل مشكلة **المدفوعات الصغيرة + التفويض القابل للقراءة آلياً** لوصول الواجهات البرمجية. هاتان مشكلتان مختلفتان.

**الحكم**: MPP ليس منافساً مباشراً لتحقيق الدخل من الواجهات البرمجية. إذا كانت حالة استخدامك هي تقسيم إيرادات Stripe بين منصة ومنشئيها، استخدم MPP. إذا كانت حالة استخدامك هي الفرض بالطلب الواحد، خاصةً من وكلاء الذكاء الاصطناعي، استخدم l402-kit.

## مقارنة مع Paddle / Lemon Squeezy

تندرج في نفس فئة Stripe — خدمات تاجر السجل المبنية حول الاشتراكات وبطاقات الائتمان. نفس مشكلة الرسوم، نفس مخاطر استرداد المدفوعات، نفس التعارض مع وكلاء الذكاء الاصطناعي.

**الحكم**: مشابه لـ Stripe. لا تداخل حقيقي مع حالة استخدام l402-kit.

## مقارنة مع x402 (Coinbase / Anthropic)

هذا أقرب منافسينا. x402 هو اقتراح بروتوكول (وليس SDK) لتوحيد مدفوعات HTTP 402، تدعمه Coinbase وتبنّته جزئياً Anthropic لاستخدام الحاسوب في Claude.

**نقاط قوة x402**:
- دعم مؤسسي (Coinbase)
- اهتمام منظومة Claude/Anthropic
- دعم USDC (عملة مستقرة، وليس Bitcoin فحسب)

**نقاط قوة l402-kit**:
- **يُشحن كوداً لا مواصفات** — x402 مسودة بروتوكول؛ l402-kit هو SDK جاهز للتثبيت الآن
- **SDK بـ 4 لغات** — TypeScript وPython وGo وRust. لا يوجد SDK منشور لـ x402 بأي لغة (حتى مايو 2026)
- **الوضع المُدار** — `ManagedProvider` يعني إعداداً صفرياً لعقدة Lightning؛ x402 يتطلب تشغيل بنية تحتية
- **وثائق بـ 11 لغة** — وثائق x402 بالإنجليزية فقط
- **مفتوح المصدر + MIT** — مواصفة x402 مفتوحة لكن لا يوجد تطبيق مرجعي منشور

**المخاطرة**: تُشحن Coinbase SDK كاملاً لـ x402. **ميزتنا التنافسية**: سنكون المكتبة المتوافقة مع x402 — يمكن لـ `l402-kit` اعتماد مواصفة x402 عند اكتمالها. البروتوكول متوافق.

**الحكم**: راقب عن كثب. كن مستعداً لإضافة توافق x402. اشحن أسرع.

## مقارنة مع BTCPay Server

BTCPay هو معالج مدفوعات Bitcoin ذاتي الاستضافة — فواتير وصفحات دفع ونقاط بيع.

**BTCPay**: حل تجاري متكامل، يعتمد على الواجهة أولاً، يتطلب إعداد خادم، لا يوجد SDK وسيط للمطورين.

**l402-kit**: يعتمد على الكود أولاً، 3 أسطر، لا خادم لإدارته، مبني للواجهات البرمجية لا صفحات الدفع.

**الحكم**: منتجان مختلفان. مستخدمو BTCPay الراغبون في تحقيق الدخل من الواجهات البرمجية هم جمهور طبيعي لـ l402-kit.

## مقارنة مع ln.bot

[ln.bot](https://ln.bot) خدمة مستضافة تتيح للمطورين تحقيق الدخل من نقاط نهاية الواجهات البرمجية بمدفوعات Lightning Network. هو أقرب منتج إلى l402-kit في السوق.

**نقاط قوة ln.bot**:
- مستضاف — لا حاجة لعقدة Lightning Network
- لوحة تحكم بسيطة لتسجيل نقاط النهاية
- يتولى إنشاء الفواتير والتحقق من المدفوعات

**نقاط قوة l402-kit**:
- **يعتمد على الكود لا لوحة التحكم** — 3 أسطر من الوسيط مقابل تسجيل نقاط النهاية في واجهة مستخدم. يندمج بشكل طبيعي في CI/CD.
- **متعدد اللغات** — ln.bot يستهدف Node.js. يُشحن l402-kit بـ TypeScript وPython وGo وRust.
- **بروتوكول L402 القياسي** — قابل للتشغيل البيني مع أي عميل يدعم L402 (Claude، وكلاء مخصصون، محافظ مستقبلية). يستخدم ln.bot تدفقاً خاصاً.
- **الوضع المستقل** — وصّل عقدة Lightning Network الخاصة بك برسوم 0%. ln.bot دائماً مستضاف.
- **SDK لوكيل الذكاء الاصطناعي** — ضوابط الميزانية، خادم MCP، أداة LangChain. لا توجد بدائل وكيل في ln.bot.
- **مفتوح المصدر (MIT)** — ln.bot مغلق المصدر.

**الحكم**: إذا أردت لوحة تحكم سريعة لتحقيق الدخل من نقطة نهاية أو اثنتين، فإن ln.bot يؤدي الغرض. إذا كنت تبني منتجاً، تشحن عبر لغات متعددة، أو تحتاج دعم وكلاء الذكاء الاصطناعي، فإن l402-kit هو الخيار الصحيح.

## مقارنة مع OpenNode / Strike API / Lightspark

هذه مزودو بنية تحتية لـ Lightning Network — توفر واجهات برمجية لإنشاء الفواتير.

**هم مزودون لا منافسون** — يستخدمهم l402-kit (OpenNodeProvider، BlinkProvider). المطور الذي يستخدم واجهة OpenNode البرمجية لا يزال بحاجة إلى l402-kit لمعالجة منطق وسيط L402.

**الحكم**: هم شركاؤنا في المنظومة.

## مزايانا الفريدة (ما لا يملكه أحد غيرنا)

### 1. وسيط متكامل (لا مجرد بروتوكول)
كل منافس هو إما معالج مدفوعات (Stripe) أو مواصفة بروتوكول (x402). نحن الـ SDK الوسيط الوحيد الجاهز للاستخدام لكل من TypeScript وPython.

### 2. ثلاثة أسطر، أي واجهة Lightning Network خلفية

**الوضع المُدار** (بدون عقدة Lightning Network — 0.3% ثابتة):
```typescript
import { ManagedProvider } from "l402-kit";
const lightning = ManagedProvider.fromAddress("you@yourdomain.com");
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

**الوضع المستقل** (عقدتك الخاصة — رسوم 0%):
```typescript
import { BlinkProvider } from "l402-kit";
const lightning = new BlinkProvider(process.env.BLINK_KEY!, process.env.BLINK_WALLET_ID!);
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

يعمل في **ثوانٍ** — بينما تستغرق Stripe 30 دقيقة من النماذج والتحقق من الهوية والتحقق البنكي.

### 3. دعم Python
لا يوجد حل L402/x402 آخر يمتلك Python SDK. المنظومة الكاملة لـ FastAPI/Flask (حوالي 40% من مطوري الواجهات البرمجية) لا يوجد لها خيار آخر.

### 4. متوافق بالفطرة مع وكلاء الذكاء الاصطناعي
تدفق L402 هو بالضبط ما تحتاجه وكلاء الذكاء الاصطناعي: قائم على HTTP، بدون متصفح، بدون OAuth، إثبات الدفع في الرأسية. Stripe يتطلب إنساناً يحمل بطاقة ائتمان. l402-kit لا يتطلب شيئاً — يدفع الوكيل برمجياً.

### 5. الحماية من إعادة الاستخدام مدمجة
التحقق التشفيري SHA-256 + الحماية من إعادة الاستخدام في الذاكرة جاهزان فوراً. الأدوات الأخرى لم تعش طويلاً بما يكفي لحل هذه المشكلة.

### 6. تجربة مطور بـ 11 لغة
الوثائق وواجهة الإضافة وملفات README بـ EN/PT/ES/ZH/JA/FR/DE/RU/HI/AR/IT — تستهدف مجتمع المطورين العالمي، لا المطورين الناطقين بالإنجليزية فحسب.
