## vs. Stripe

**Stripe выигрывает в**: KYC, периодическом выставлении счетов, UX с кредитными картами, обнаружении мошенничества, корпоративных контрактах.

**l402-kit выигрывает в**: микроплатежах (< $0.01), ИИ-агентах, глобальном охвате, нулевых возвратах, нулевой настройке, мгновенном расчёте.

Минимальная комиссия Stripe составляет $0.30 + 2.9%. Платёж в 1 sat ($0.0006) через Stripe обошёлся бы в 50 000% комиссий. l402-kit берёт фиксированные 0.3% — и больше ничего.

**Вывод**: Они не конкуренты. Stripe — для подписок. l402-kit — для микроплатежей за каждый вызов API. Многие проекты будут использовать оба решения.

## vs. MPP (Stripe + Tempo) — новинка, март 2026

Multi-Party Payments (MPP) — новый протокол, анонсированный Stripe и Tempo в марте 2026 года. Он позволяет двум сторонам разделить платёж Stripe в момент оформления — например, маркетплейс берёт 10%, а продавец 90%, всё в одной транзакции.

**Сильные стороны MPP**:
- Институциональная поддержка (вся торговая сеть Stripe)
- Привычный UX с кредитными картами
- Встроенные KYC и соответствие требованиям
- Автоматическое распределение выручки

**Где MPP уступает для монетизации API**:
- **Минимальная комиссия по-прежнему $0.30** — MPP не меняет экономику транзакций Stripe. Микроплатёж в 1 sat по-прежнему экономически невозможен.
- **Нет поддержки ИИ-агентов** — требует человека с кредитной картой и браузером. Автономный агент не может совершить платёж через MPP.
- **Обе стороны должны быть клиентами Stripe** — нет доступа без разрешения.
- **Расчёт по-прежнему занимает 2–7 дней** — нет расчётов в реальном времени.
- **Нет криптографического доказательства** — плательщик всё ещё может оспорить платёж или запросить возврат.

MPP решает проблему **разделения выручки** для платежей маркетплейсов. L402 решает проблему **микроплатежей + машиночитаемой авторизации** для доступа к API. Это разные задачи.

**Вывод**: MPP не является прямым конкурентом для монетизации API. Если ваш сценарий — разделение выручки Stripe между платформой и авторами контента, используйте MPP. Если ваш сценарий — плата за каждый вызов API, особенно от ИИ-агентов, используйте l402-kit.

## vs. Paddle / Lemon Squeezy

Та же категория, что и Stripe — сервисы торгового посредника, построенные вокруг подписок и кредитных карт. Та же проблема комиссий, тот же риск возвратов, та же несовместимость с ИИ-агентами.

**Вывод**: Аналогично Stripe. Реального пересечения с областью применения l402-kit нет.

## vs. x402 (Coinbase / Anthropic)

Это наш ближайший конкурент. x402 — предложение протокола (не SDK) для стандартизации HTTP 402 платежей, поддержанное Coinbase и частично принятое Anthropic для компьютерного использования Claude.

**Сильные стороны x402**:
- Институциональная поддержка (Coinbase)
- Интерес экосистемы Claude/Anthropic
- Поддержка USDC (стейблкоин, не только Bitcoin)

**Сильные стороны l402-kit**:
- **Поставляет код, а не спецификации** — x402 является черновиком протокола; l402-kit — это рабочий SDK, который можно установить сегодня
- **SDK на 4 языках** — TypeScript, Python, Go, Rust. У x402 нет опубликованного SDK ни на одном языке (по состоянию на май 2026)
- **Управляемый режим** — `ManagedProvider` означает нулевую настройку Lightning-ноды; x402 требует запуска инфраструктуры
- **Документация на 11 языках** — у x402 документация только на английском
- **Открытый исходный код + MIT** — спецификация x402 открыта, но эталонная реализация не опубликована

**Риск**: Coinbase выпускает полный x402 SDK. **Наше преимущество**: мы станем библиотекой, совместимой с x402 — `l402-kit` может принять спецификацию x402 после её финализации. Протоколы совместимы.

**Вывод**: Следить внимательно. Быть готовым добавить совместимость с x402. Двигаться быстрее.

## vs. BTCPay Server

BTCPay — самостоятельно размещаемый процессор платежей Bitcoin: счета, страницы оформления, POS-терминалы.

**BTCPay**: полноценное торговое решение, ориентированное на UI, требует настройки сервера, нет SDK middleware для разработчиков.

**l402-kit**: ориентирован на код, 3 строки, не нужно управлять сервером, создан для API, а не страниц оформления.

**Вывод**: Разные продукты. Пользователи BTCPay, которым нужна монетизация API, — естественная аудитория для l402-kit.

## vs. ln.bot

[ln.bot](https://ln.bot) — хостинговый сервис, позволяющий разработчикам монетизировать API-эндпоинты с помощью Lightning-платежей. Это наиболее близкий к l402-kit продукт на рынке.

**Сильные стороны ln.bot**:
- Хостинг — Lightning-нода не требуется
- Простая панель управления для регистрации эндпоинтов
- Обрабатывает создание счетов и проверку платежей

**Сильные стороны l402-kit**:
- **Ориентирован на код, а не на панель управления** — 3 строки middleware против регистрации эндпоинтов в UI. Органично вписывается в CI/CD.
- **Многоязычный** — ln.bot ориентирован на Node.js. l402-kit поставляется на TypeScript, Python, Go и Rust.
- **Стандартный протокол L402** — совместим с любым L402-совместимым клиентом (Claude, кастомные агенты, будущие кошельки). ln.bot использует проприетарный поток.
- **Суверенный режим** — подключите собственную Lightning-ноду с комиссией 0%. ln.bot всегда работает на хостинге.
- **SDK для ИИ-агентов** — бюджетный контроль, MCP-сервер, инструмент LangChain. У ln.bot нет примитивов для агентов.
- **Открытый исходный код (MIT)** — ln.bot имеет закрытый исходный код.

**Вывод**: Если вам нужна быстрая панель управления для монетизации одного-двух эндпоинтов, ln.bot подойдёт. Если вы создаёте продукт, работаете на нескольких языках или нуждаетесь в поддержке ИИ-агентов, l402-kit — правильный выбор.

## vs. OpenNode / Strike API / Lightspark

Это поставщики Lightning-инфраструктуры — они предоставляют API для создания счетов.

**Они являются поставщиками, а не конкурентами** — l402-kit использует их (OpenNodeProvider, BlinkProvider). Разработчик, использующий API OpenNode, всё равно нуждается в l402-kit для обработки логики L402 middleware.

**Вывод**: Они — партнёры нашей экосистемы.

## Наши уникальные преимущества (чего нет ни у кого другого)

### 1. Полноценный middleware (не просто протокол)
Каждый конкурент — это либо платёжный процессор (Stripe), либо спецификация протокола (x402). Мы — единственный готовый к использованию middleware SDK как для TypeScript, так и для Python.

### 2. Три строки, любой Lightning-бэкенд

**Управляемый режим** (без Lightning-ноды — фиксированные 0.3%):
```typescript
import { ManagedProvider } from "l402-kit";
const lightning = ManagedProvider.fromAddress("you@yourdomain.com");
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

**Суверенный режим** (ваша собственная нода — комиссия 0%):
```typescript
import { BlinkProvider } from "l402-kit";
const lightning = new BlinkProvider(process.env.BLINK_KEY!, process.env.BLINK_WALLET_ID!);
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

Работает **за секунды** — в то время как Stripe требует 30 минут форм, KYC и банковской верификации.

### 3. Поддержка Python
Ни одно другое решение L402/x402 не имеет Python SDK. Вся экосистема FastAPI/Flask (~40% разработчиков API) не имеет другого варианта.

### 4. Нативная поддержка ИИ-агентов
Поток L402 — это именно то, что нужно ИИ-агентам: на основе HTTP, без браузера, без OAuth, доказательство оплаты в заголовке. Stripe требует человека с кредитной картой. l402-kit ничего не требует — агент платит программно.

### 5. Встроенная защита от повторных атак
SHA256 криптографическая верификация + защита от повторного использования в памяти из коробки. Другие инструменты не существуют достаточно долго, чтобы решить эту проблему.

### 6. Опыт разработчика на 11 языках
Документация, UI расширения и README на EN/PT/ES/ZH/JA/FR/DE/RU/HI/AR/IT — ориентированы на глобальное сообщество разработчиков, а не только на англоязычных разработчиков.

## Риски и меры по их снижению

| Риск | Вероятность | Меры снижения |
|---|---|---|
| Coinbase выпускает полный x402 SDK | Средняя | Добавить совместимость со спецификацией x402, стать эталонной реализацией x402 |
| Распространение Lightning замедляется | Низкая | Добавить поддержку USDC/USDT через тот же протокол |
| Stripe добавляет микроплатежи | Очень низкая | У них было 15 лет, и они этого не сделали — структурно несовместимо с их моделью |
| Серьёзная уязвимость безопасности | Низкая | 409 автоматизированных тестов на 5 средах выполнения, SHA256 верификация, защита от повторных атак |
| Поставщик (Blink) выходит из строя | Средняя | Не привязан к поставщику — переключиться на OpenNode/LNbits в 1 строку |
