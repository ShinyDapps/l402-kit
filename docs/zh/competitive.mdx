## 对比 Stripe

**Stripe 的优势**：KYC 认证、循环计费、信用卡用户体验、欺诈检测、企业合同。

**l402-kit 的优势**：微支付（< $0.01）、AI 智能体、全球覆盖、零退款争议、零配置、即时结算。

Stripe 的最低手续费为 $0.30 + 2.9%。一笔 1 sat 的支付（约 $0.0006）在 Stripe 上的手续费占比高达 50,000%。l402-kit 仅收取 0.3% 固定费率，无其他费用。

**结论**：两者并非竞争关系。Stripe 适用于订阅场景，l402-kit 适用于按调用次数计费的微支付场景。许多项目会同时使用两者。

---

## 对比 MPP（Stripe + Tempo）——2026 年 3 月新推出

多方支付（MPP）是 Stripe 和 Tempo 于 2026 年 3 月联合发布的新协议。它允许双方在结账时拆分 Stripe 支付——例如，平台抽取 10%，卖家获得 90%，通过单笔交易完成结算。

**MPP 的优势**：
- 机构背书（Stripe 完整的商户网络）
- 熟悉的信用卡用户体验
- 内置 KYC 和合规能力
- 自动处理收益分成

**MPP 在 API 变现方面的不足**：
- **最低手续费仍为 $0.30**——MPP 并未改变 Stripe 的单笔交易经济模型。1 sat 的微支付在经济上仍然不可行。
- **不支持 AI 智能体**——需要有人持有信用卡并通过浏览器操作。自主智能体无法发起 MPP 支付。
- **要求双方均为 Stripe 客户**——无法实现无需许可的访问。
- **结算仍需 2–7 天**——不支持实时结算。
- **无密码学证明**——付款方仍可发起争议或退款。

MPP 解决的是市场支付中的**收益分成**问题。L402 解决的是 API 访问中的**微支付 + 机器可读授权**问题。这是两个截然不同的问题。

**结论**：MPP 并非 API 变现领域的直接竞争对手。如果您的需求是在平台与内容创作者之间拆分 Stripe 收益，请使用 MPP。如果您的需求是按 API 调用次数收费，尤其是面向 AI 智能体，请使用 l402-kit。

## 对比 Paddle / Lemon Squeezy

与 Stripe 同属一类——围绕订阅和信用卡构建的商户记录服务。手续费问题相同，退款争议风险相同，同样不兼容 AI 智能体。

**结论**：与 Stripe 相同。与 l402-kit 的使用场景几乎没有重叠。

---

## 对比 x402（Coinbase / Anthropic）

这是我们最接近的竞争对手。x402 是一项协议提案（而非 SDK），旨在标准化 HTTP 402 支付，由 Coinbase 背书，并被 Anthropic 部分采用于 Claude 的计算机使用功能。

**x402 的优势**：
- 机构背书（Coinbase）
- Claude/Anthropic 生态系统的关注
- 支持 USDC（稳定币，不仅限于比特币）

**l402-kit 的优势**：
- **交付代码，而非规范**——x402 仍是草案协议；l402-kit 是可立即安装使用的工作 SDK
- **4 语言 SDK**——TypeScript、Python、Go、Rust。截至 2026 年 5 月，x402 尚未发布任何语言的 SDK
- **托管模式**——`ManagedProvider` 实现零 Lightning 节点配置；x402 需要自行运行基础设施
- **11 种语言文档**——x402 仅提供英文文档
- **开源 + MIT 协议**——x402 规范开放，但尚未发布参考实现

**潜在风险**：Coinbase 推出完整的 x402 SDK。**我们的护城河**：我们将成为兼容 x402 的库——当 x402 规范最终确定时，`l402-kit` 可以采纳该规范。两个协议具有兼容性。

**结论**：密切关注。做好添加 x402 兼容性的准备。加速交付。

## 对比 BTCPay Server

BTCPay 是一个自托管的比特币支付处理器，提供发票、结账页面和 POS 终端功能。

**BTCPay**：完整的商户解决方案，以 UI 为核心，需要服务器配置，无开发者中间件 SDK。

**l402-kit**：以代码为核心，3 行集成，无需管理服务器，专为 API 而非结账页面而设计。

**结论**：产品定位不同。希望实现 API 变现的 BTCPay 用户是 l402-kit 的天然目标受众。

---

## 对比 ln.bot

[ln.bot](https://ln.bot) 是一项托管服务，允许开发者通过 Lightning 支付对 API 端点进行变现。它是市场上与 l402-kit 最接近的产品。

**ln.bot 的优势**：
- 托管服务——无需 Lightning 节点
- 简洁的控制台用于注册端点
- 处理发票创建和支付验证

**l402-kit 的优势**：
- **以代码为核心，而非控制台**——3 行中间件 vs. 在 UI 中注册端点，天然融入 CI/CD 流程。
- **多语言支持**——ln.bot 面向 Node.js。l402-kit 提供 TypeScript、Python、Go 和 Rust 支持。
- **标准 L402 协议**——可与任何支持 L402 的客户端互操作（Claude、自定义智能体、未来钱包）。ln.bot 使用专有流程。
- **自主模式**——连接您自己的 Lightning 节点，手续费为 0%。ln.bot 始终为托管模式。
- **AI 智能体 SDK**——预算控制、MCP 服务器、LangChain 工具。ln.bot 不具备智能体原语。
- **开源（MIT）**——ln.bot 为闭源。

**结论**：如果您只需要一个快速控制台来对一两个端点进行变现，ln.bot 可以满足需求。如果您在构建产品、跨语言交付或需要 AI 智能体支持，l402-kit 是正确的选择。

## 对比 OpenNode / Strike API / Lightspark

这些是 Lightning 基础设施提供商——提供发票创建 API。

**它们是提供商，而非竞争对手**——l402-kit 使用它们（OpenNodeProvider、BlinkProvider）。使用 OpenNode API 的开发者仍然需要 l402-kit 来处理 L402 中间件逻辑。

**结论**：它们是我们的生态系统合作伙伴。

## 我们的独特优势（其他产品所不具备的）

### 1. 全栈中间件（不仅仅是协议）
所有竞争对手要么是支付处理器（Stripe），要么是协议规范（x402）。我们是唯一一个同时支持 TypeScript 和 Python 的即用型中间件 SDK。

### 2. 三行代码，兼容任意 Lightning 后端

**托管模式**（无需 Lightning 节点——0.3% 固定费率）：
```typescript
import { ManagedProvider } from "l402-kit";
const lightning = ManagedProvider.fromAddress("you@yourdomain.com");
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

**自主模式**（使用您自己的节点——0% 手续费）：
```typescript
import { BlinkProvider } from "l402-kit";
const lightning = new BlinkProvider(process.env.BLINK_KEY!, process.env.BLINK_WALLET_ID!);
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

**数秒即可完成**——而 Stripe 需要 30 分钟填写表单、完成 KYC 和银行验证。

### 3. Python 支持
没有其他 L402/x402 解决方案提供 Python SDK。整个 FastAPI/Flask 生态系统（约占 API 开发者的 40%）没有其他选择。

### 4. 原生 AI 智能体支持
L402 流程正是 AI 智能体所需要的：基于 HTTP、无需浏览器、无需 OAuth、支付证明直接包含在请求头中。Stripe 需要持有信用卡的人类用户，l402-kit 则没有任何限制——智能体可以通过编程方式完成支付。

### 5. 内置防重放攻击
SHA256 密码学验证 + 开箱即用的内存重放保护。其他工具尚未经历足够长的时间来解决这一问题。

### 6. 11 种语言的开发者体验
文档、扩展 UI 和 README 提供 EN/PT/ES/ZH/JA/FR/DE/RU/HI/AR/IT 多语言版本——面向全球开发者社区，而非仅限于英语开发者。
