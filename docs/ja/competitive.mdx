## vs. Stripe

**Stripeが優れている点**: KYC、定期課金、クレジットカードUX、不正検知、エンタープライズ契約。

**l402-kitが優れている点**: マイクロペイメント（$0.01未満）、AIエージェント、グローバルリーチ、チャージバックゼロ、セットアップゼロ、即時決済。

Stripeの最低手数料は$0.30 + 2.9%です。Stripeでの1 satペイメント（$0.0006）は手数料が50,000%になります。l402-kitは一律0.3%のみ — それ以外はかかりません。

**結論**: 競合ではありません。Stripeはサブスクリプション向けです。l402-kitはコール単位のマイクロペイメント向けです。多くのプロジェクトは両方を使用するでしょう。

## vs. MPP（Stripe + Tempo）— 2026年3月新登場

マルチパーティペイメント（MPP）は、2026年3月にStripeとTempoが発表した新しいプロトコルです。チェックアウト時に2者間でStripeの支払いを分割できます — 例えば、マーケットプレイスが10%、ベンダーが90%を受け取り、1回のトランザクションで決済されます。

**MPPの強み**:
- 機関的なバックアップ（Stripeのマーチャントネットワーク全体）
- 馴染みのあるクレジットカードUX
- 組み込みのKYCとコンプライアンス
- 収益分配の自動処理

**MPPがAPIマネタイズにおいて不十分な点**:
- **最低手数料は依然として$0.30** — MPPはStripeのトランザクションあたりの経済性を変えません。1 satのマイクロペイメントは経済的に依然として不可能です。
- **AIエージェント非対応** — クレジットカードとブラウザを持つ人間が必要です。自律型エージェントはMPP支払いを行えません。
- **両者がStripeカスタマーである必要あり** — パーミッションレスなアクセスはできません。
- **決済にはまだ2〜7日かかる** — リアルタイム決済ではありません。
- **暗号証明なし** — 支払者は依然として異議申し立て/チャージバックが可能です。

MPPはマーケットプレイス決済の**収益分配**問題を解決します。L402はAPIアクセスの**マイクロペイメント + 機械可読な認証**問題を解決します。これらは異なる問題です。

**結論**: MPPはAPIマネタイズの直接的な競合ではありません。プラットフォームとクリエイター間でStripeの収益を分配するユースケースであればMPPを使用してください。APIコール単位で課金するユースケース、特にAIエージェントからの場合はl402-kitを使用してください。

## vs. Paddle / Lemon Squeezy

Stripeと同じカテゴリ — サブスクリプションとクレジットカードを中心に構築されたマーチャント・オブ・レコードサービスです。同じ手数料の問題、同じチャージバックリスク、同じAIエージェントとの非互換性があります。

**結論**: Stripeと同様です。l402-kitのユースケースとの実質的な重複はありません。

---

## vs. x402（Coinbase / Anthropic）

これが最も近い競合です。x402はHTTP 402決済を標準化するためのプロトコル提案（SDKではない）で、Coinbaseがサポートしており、AnthropicがClaudeのコンピューター使用に部分的に採用しています。

**x402の強み**:
- 機関的なバックアップ（Coinbase）
- Claude/Anthropicエコシステムへの関心
- USDCサポート（ステーブルコイン、Bitcoinだけでない）

**l402-kitの強み**:
- **仕様ではなくコードを提供** — x402はドラフトプロトコル; l402-kitは今日インストールして使えるSDKです
- **4言語対応SDK** — TypeScript、Python、Go、Rust。x402はいずれの言語でも公開SDKなし（2026年5月時点）
- **マネージドモード** — `ManagedProvider`によりLightning Networkノードのセットアップがゼロ; x402はインフラの構築が必要
- **11言語のドキュメント** — x402は英語のみ
- **オープンソース + MIT** — x402の仕様はオープンですが、リファレンス実装は未公開

**リスク**: CoinbaseがフルのX402 SDKをリリースする可能性があります。**私たちの強み**: l402-kitはx402互換ライブラリになれます — x402の仕様が確定した際にl402-kitで採用可能です。プロトコルには互換性があります。

**結論**: 注意深くモニタリングしてください。x402互換性の追加に備えてください。より速く提供してください。

---

## vs. BTCPay Server

BTCPayはセルフホスト型のBitcoin決済プロセッサ — 請求書、チェックアウトページ、POSターミナルを備えています。

**BTCPay**: フルマーチャントソリューション、UI優先、サーバーセットアップが必要、開発者向けミドルウェアSDKなし。

**l402-kit**: コード優先、3行、管理するサーバーなし、チェックアウトではなくAPIのために構築。

**結論**: 異なる製品です。APIマネタイズを求めるBTCPayユーザーは、l402-kitの自然な対象ユーザーです。

---

## vs. ln.bot

[ln.bot](https://ln.bot)は、開発者がLightning Network決済でAPIエンドポイントをマネタイズできるホスト型サービスです。市場においてl402-kitに最も近い製品です。

**ln.botの強み**:
- ホスト型 — Lightning Networkノード不要
- エンドポイント登録用のシンプルなダッシュボード
- 請求書作成と支払い検証を処理

**l402-kitの強み**:
- **ダッシュボード優先ではなくコード優先** — UIでエンドポイントを登録するのではなく3行のミドルウェア。CI/CDに自然にフィット。
- **多言語対応** — ln.botはNode.jsを対象としています。l402-kitはTypeScript、Python、Go、Rustを提供。
- **標準L402プロトコル** — L402対応クライアント（Claude、カスタムエージェント、将来のウォレット）との相互運用が可能。ln.botは独自フローを使用。
- **ソブリンモード** — 自分のLightning Networkノードを0%手数料で接続可能。ln.botは常にホスト型。
- **AIエージェントSDK** — 予算制御、MCPサーバー、LangChainツール。ln.botにはエージェントプリミティブがない。
- **オープンソース（MIT）** — ln.botはクローズドソース。

**結論**: 1〜2つのエンドポイントを素早くマネタイズするダッシュボードが欲しい場合、ln.botは機能します。製品を構築する場合、複数言語で提供する場合、またはAIエージェントのサポートが必要な場合は、l402-kitが正しい選択です。

## vs. OpenNode / Strike API / Lightspark

これらはLightning Networkインフラプロバイダーで、請求書作成APIを提供しています。

**これらはプロバイダーであり、競合ではありません** — l402-kitはこれらを使用しています（OpenNodeProvider、BlinkProvider）。OpenNodeのAPIを使う開発者も、L402ミドルウェアロジックを処理するためにl402-kitが必要です。

**結論**: エコシステムパートナーです。

## 独自の優位性（他にないもの）

### 1. フルスタックミドルウェア（プロトコルだけではない）
すべての競合は、決済プロセッサ（Stripe）かプロトコル仕様（x402）のどちらかです。TypeScriptとPythonの両方に対応した、すぐに使えるミドルウェアSDKは私たちだけです。

### 2. 3行で、任意のLightning Networkバックエンド

**マネージドモード**（Lightning Networkノード不要 — 一律0.3%）:
```typescript
import { ManagedProvider } from "l402-kit";
const lightning = ManagedProvider.fromAddress("you@yourdomain.com");
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

**ソブリンモード**（自分のノード — 0%手数料）:
```typescript
import { BlinkProvider } from "l402-kit";
const lightning = new BlinkProvider(process.env.BLINK_KEY!, process.env.BLINK_WALLET_ID!);
app.get("/premium", l402({ priceSats: 100, lightning }), handler);
```

**数秒で動作** — Stripeがフォーム、KYC、銀行確認で30分かかるのに対して。

### 3. Pythonサポート
他のL402/x402ソリューションにはPython SDKがありません。FastAPI/Flaskエコシステム全体（API開発者の約40%）には他の選択肢がありません。

### 4. AIエージェントネイティブ
L402フローはAIエージェントに必要なものそのものです: HTTPベース、ブラウザ不要、OAuth不要、ヘッダーに支払い証明。Stripeはクレジットカードを持つ人間を必要とします。l402-kitは何も必要としません — エージェントがプログラムで支払います。

### 5. リプレイ防止を内蔵
SHA256暗号検証 + インメモリリプレイ防止がすぐに使えます。他のツールはこれを解決するほど長く存在していません。

### 6. 11言語の開発者エクスペリエンス
EN/PT/ES/ZH/JA/FR/DE/RU/HI/AR/ITのドキュメント、拡張機能UI、README — 英語圏の開発者だけでなく、グローバルな開発者コミュニティを対象としています。

## リスクと軽減策

| リスク | 可能性 | 軽減策 |
|---|---|---|
| CoinbaseがフルのX402 SDKをリリース | 中 | x402仕様の互換性を追加し、x402のリファレンス実装になる |
| Lightning Networkの普及が停滞 | 低 | 同じプロトコルでUSDC/USDTサポートを追加 |
| Stripeがマイクロペイメントを追加 | 非常に低 | 15年あっても実現していない — 構造的にそのモデルと非互換 |
| 重大なセキュリティバグ | 低 | 5つのランタイムにわたる409件の自動テスト、SHA256検証、リプレイ防止 |
| プロバイダー（Blink）がダウン | 中 | プロバイダー非依存 — 1行でOpenNode/LNbitsに切り替え可能 |
